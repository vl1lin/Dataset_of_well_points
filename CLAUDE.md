# CLAUDE.md — сайт выборки данных Dataset_of_well_points

Статичная HTML-страница для выборки данных из CSV-таблиц базы Dataset_of_well_points
(источник: Мищенко И.Т., Палий В.О. «Газожидкостные потоки в нефтяных скважинах», 2018).
Хостинг — **GitHub Pages**. Сервера нет, вся логика выполняется в браузере на JavaScript.

---

## 1. Как работать в этом репозитории

- Работаем **по этапам** (раздел 9). Каждый этап нужно согласовать до начала, а после него объяснить, что сделано и почему. Готовые большие куски кода выдавай только по прямой просьбе.
- Язык общения, комментариев и интерфейса — русский. Имена переменных и функций пишутся на английском.
- Не усложняй там, где это не требуется. Рефакторь только ту часть кода, которую нужно изменить.
- Если требование неоднозначно, сначала задай вопрос, а не выбирай молча.

## 2. Технологии и ограничения

- Чистый HTML + CSS + JavaScript (ES-модули), **без сборки** (без npm/webpack/React). Страница должна работать сразу после пуша на GitHub Pages.
- Внешние библиотеки подключаются только с CDN, версия закрепляется точно (никаких `@latest`):
  - **Papa Parse** читает CSV (кавычки, запятые внутри полей, переводы строк CRLF);
  - **SheetJS (xlsx)** формирует выгрузку в .xlsx;
  - **DuckDB-WASM** — движок конструктора выборки и SQL-режима. Загружается лениво, только при первом открытии панели, потому что весит несколько МБ;
  - **Pyodide** (Python + pandas в браузере) — вспомогательный Python-режим. Загружается только при первом переключении на вкладку «Python» (10–20 МБ) и работает в Web Worker, чтобы страница не зависала.
- Типизация: `// @ts-check` в начале каждого JS-файла и JSDoc-типы (`@typedef`, `@param`, `@returns`) для всех функций.
- В начале каждого модуля пишется комментарий со схемой взаимодействия: какие функции он экспортирует, кто их вызывает и какие данные передаются.
- Каждая функция получает JSDoc: что принимает, что возвращает, что делает.
- Физические величины указываются с единицами в именах, если есть неоднозначность (`pressure_mpa`, `depth_m`).
- **Локально через `file://` страница не работает**: браузер блокирует `fetch` соседних CSV. Для проверки поднимай сервер `python -m http.server` в корне репозитория и открывай `http://localhost:8000`.

```

  data.js        — загрузка и парсинг CSV, приведение типов
  columns.js     — словарь: колонка → русское название, группы колонок (PVT и т.п.)
  filters.js     — UI: мультиселекты месторождений и скважин, флаги
  query.js       — логика выборки (аналог SQL-запроса на JS), без работы с DOM
  render.js      — вкладки по месторождениям и HTML-таблицы
  export.js      — выгрузка в .xlsx
  panel.js           — выдвижная боковая панель и переключение режимов (Конструктор / SQL / Python)
  builder-ui.js      — UI конструктора выборки
  builder-sql.js     — состояние конструктора → текст SQL (чистая функция, без DOM)
  schema.js          — описание схемы: таблицы, типы колонок, ключи связи, группы колонок
  duckdb.js          — загрузка DuckDB-WASM, создание таблиц из CSV, выполнение запроса
  python-worker.js   — Web Worker с Pyodide: загрузка pandas, выполнение кода
  python-panel.js    — UI Python-режима, обмен сообщениями с воркером
```

## 4. Данные

Формат CSV: UTF-8, разделитель запятая, десятичный разделитель точка, пустое поле означает NULL, строки заканчиваются CRLF.
**Технические колонки `note`, `source`, `book_table` не выводятся** ни в таблицах на странице, ни в выгрузке .xlsx. В данных они остаются.

| Файл | Строк | Ключи |
|---|---|---|
| `01_fields.csv` | 35 | `code` (ПШ, ВЗ, УС…) |
| `02_fluids.csv` | 6 | `field_code` + `horizon` |
| `03_studies.csv` | 455 | `study_code` (уникален), `field_code`, `well` |
| `04_points.csv` | 4327 | `study_code` |
| `05_pump_intake.csv` | 107 | `field_code`, `well` (только ТМ, РМ, СФ) |

Особенности данных, которые нужно учитывать в коде:
- **`well` не уникален**: одна скважина может иметь до 18 исследований. Настоящий ключ — `study_code`. Пара «месторождение + скважина» уникальна только в пределах месторождения.
- **У 23 исследований `well` пустой** (номер потерян в OCR). В списке скважин они показываются как «без номера (<study_code>)» и должны попадать в выборку.
- `study_year` / `study_month` часто пустые (224 исследования без даты).
- В `05_pump_intake.csv` много скважин, которых нет в `studies` (РМ: 39 скважин, совпадают только 7). Список скважин строится как **объединение** скважин из `studies` и `pump_intake`, если флаг «Скрыть режим работы» снят.
- `fluids` связан с месторождением через `field_code`. У большинства месторождений строк в `fluids` нет, это нормальная ситуация, а не ошибка.

## 5. Интерфейс

### 5.1 Панель выбора (ручного ввода нет, только выбор из всплывающих списков)

1. **Месторождения** — мультиселект (чекбоксы во всплывающем списке, подпись `Название (код)`).
   Под ним галочка **«Выбрать все»**: при включении отбор идёт по всем месторождениям, а мультиселект блокируется.
2. **Скважины** — мультиселект, список **сгруппирован по выбранным месторождениям**.
   У каждой группы есть своя галочка **«Выбрать все скважины месторождения»**.
   При смене месторождений список пересобирается, а выбор скважин из убранных месторождений сбрасывается.
3. Флаги:
   - **«Показать PVT-свойства»** (по умолчанию выключен);
   - **«Скрыть режим работы ЭЦН/ШСН»** (по умолчанию выключен). Если включён, данные раздела 2 (`05_pump_intake.csv`) не подтягиваются.
4. Кнопки **«Показать»** и **«Скачать .xlsx»** (вторая неактивна, пока нет результата).

### 5.2 Вывод результата

- Над результатом идут **вкладки — по одной на каждое выбранное месторождение** (как листы Excel). Если месторождение одно, вкладка тоже одна.
- Внутри вкладки таблицы расположены друг под другом, у каждой есть заголовок.
- Если для таблицы нет данных, вместо неё выводится строка «Нет данных для выбранных скважин».
- Сортировка: по `well` (естественная: 2Ф < 10Ф), затем по `study_code`. Точки сортируются по `study_code`, затем по `depth_m`.

## 6. Таблицы результата (для каждого месторождения)

**Таблица 1. Исследования**
`well, study_code, horizon, lift_method, study_year, study_month`

**Таблица 2. Параметры исследований**
`well, study_code` + все остальные колонки `studies`, кроме:
- колонок таблицы 1 (`horizon, lift_method, study_year, study_month`), служебной `field_code` и технической `note`;
- PVT-колонок (они выводятся в таблице 4).

Колонки, **полностью пустые в текущей выборке**, скрываются.

**Таблица 3. Распределение давления и температуры**
`well, study_code, depth_m, pressure_mpa, temp_c`

**Таблица 4. PVT-свойства** (только при флаге «Показать PVT-свойства»), состоит из двух частей:
- 4а. Из `studies`: `well, study_code` + PVT-колонки `p_sat_mpa, t_res_c, gas_content_m3m3, gas_sat_m3t, gor, gor_unit, rho_oil_dead, rho_oil_res, rho_gas, rho_water`;
- 4б. Из `fluids` (свойства по залежам): все строки этого месторождения, без колонок `field_code`, `source`, `note`. Если строк нет, выводится сообщение «Свойства флюидов по залежам в книге не приведены».

**Таблица 5. Давление на приёме насосов (раздел 2)** (только если флаг «Скрыть режим работы ЭЦН/ШСН» **выключен** и есть данные)
`well, lift_method, regime, h_pump_m, h_dyn_m, p_annulus_wh_mpa, p_intake_mpa`

## 8. Выгрузка в .xlsx (`export.js`)

- Один файл `well_data_<ГГГГ-ММ-ДД>.xlsx`.
- **Один лист на каждое месторождение**. Имя листа — название месторождения (не длиннее 31 символа, символы `[]:*?/\` удаляются, дубли получают суффикс).
- Внутри листа таблицы идут **друг под другом в том же порядке, что на странице**. Перед каждой таблицей стоит строка с её заголовком, затем строка с русскими названиями колонок и данные. Между таблицами **одна пустая строка**.
- Числа записываются числами (не текстом), пустые значения — пустыми ячейками.
- Первый лист называется «Параметры запроса»: выбранные месторождения и скважины, состояние флагов и дата выгрузки.
- Результат боковой панели выгружается отдельной кнопкой в самой панели, в файл с одним листом, названным по режиму: «Конструктор», «SQL» или «Python». Заголовки колонок — русские.

## 9. Боковая панель «Работа с данными»

Выдвижная панель сбоку (кнопка-ярлык на краю экрана), открывается и закрывается без перезагрузки страницы.
Вверху панели три вкладки-режима: **Конструктор** (основной, открыт по умолчанию), **SQL**, **Python** (вспомогательный).
Все три режима работают с одними и теми же данными: таблицы `fields, fluids, studies, points, pump_intake` с именами колонок как в CSV.
Изменения данных в любом режиме не сохраняются: работа идёт над копией в браузере, об этом в панели есть подпись.

### 9.1 Конструктор выборки (основной режим)

Пользователь собирает запрос выбором, без написания кода. Шаги идут сверху вниз:

1. **Колонки.** Галочки по смысловым группам (из `schema.js`): «Идентификация» (месторождение, скважина, № исследования, горизонт, способ эксплуатации, дата), «Дебиты и обводнённость», «Геометрия», «Давления», «Температуры», «Газ», «PVT», «Замеры по глубине» (`points`), «Свойства по залежам» (`fluids`), «Режимы насосов» (`pump_intake`). Технические колонки (`note`, `source`, `book_table`) в конструкторе не предлагаются.
2. **Условия.** Строки вида «колонка → оператор → значение», добавляются кнопкой «+ условие». Переключатель для всего списка: «все условия (И)» / «любое из условий (ИЛИ)».
   - Числовые колонки: `=, ≠, >, ≥, <, ≤, между, пусто, не пусто`. Значение вводится числом, десятичный разделитель — точка или запятая.
   - Текстовые колонки: `равно одному из` / `не равно ни одному из` (значения выбираются из списка уникальных значений колонки), `пусто`, `не пусто`.
3. **Группировка (необязательно).** Колонки группировки и агрегаты: количество, среднее, минимум, максимум, сумма. Подпись агрегата: «Среднее: Забойное давление, МПа».
4. **Сортировка** по одной или нескольким выбранным колонкам, по возрастанию или убыванию.
5. Галочка **«Учитывать выбор месторождений и скважин с главной панели»** (по умолчанию включена).
6. Кнопка **«Выполнить»**.

**Автоматическое связывание таблиц.** Пользователь не думает о JOIN: `builder-sql.js` сам подбирает связи по выбранным колонкам и условиям.
- `studies ↔ points` по `study_code`;
- `studies ↔ fields` по `field_code`;
- `studies ↔ fluids` по `field_code` + `horizon` (LEFT JOIN: у большинства исследований свойств залежи нет, колонки будут пустыми);
- `pump_intake ↔ fields` по `field_code`.
- `pump_intake` **не связывается** со `studies` и `points`: общих скважин мало, связь неоднозначна. Если выбраны колонки из обеих групп, конструктор показывает сообщение и не выполняет запрос.

**Безопасность и корректность SQL.** Имена таблиц и колонок берутся только из `schema.js` (белый список). Значения из условий экранируются. Текст пользователя в SQL напрямую не подставляется.

**Под капотом** конструктор генерирует SQL и выполняет его в DuckDB-WASM. Кнопка **«Показать SQL»** раскрывает сгенерированный запрос только для чтения. Кнопка **«Открыть в SQL-режиме»** переносит запрос во вкладку SQL для ручной правки. Обратного преобразования SQL → конструктор нет, и об этом выводится предупреждение.

### 9.2 SQL-режим

- Поле для текста запроса, кнопка «Выполнить». Над полем — подсказка со списком таблиц и колонок.
- Движок — DuckDB-WASM, диалект близок к PostgreSQL. Свой парсер SQL не пишем.
- Технические колонки здесь доступны.
- Ошибка выводится текстом в панели и не ломает страницу.

### 9.3 Python-режим (вспомогательный)

- Pyodide + pandas, выполнение в Web Worker. При первом открытии вкладки показывается индикатор загрузки с пояснением, что загрузка разовая и занимает время.
- Таблицы доступны как DataFrame с теми же именами: `fields, fluids, studies, points, pump_intake`.
- Кнопка **«Передать в Python»** в конструкторе и SQL-режиме передаёт текущий результат как DataFrame `df`.
- Поле для кода и кнопка «Выполнить». Результатом считается переменная `result` (DataFrame). Если её нет, используется значение последнего выражения, если это DataFrame. Вывод `print()` показывается отдельно под кодом.
- Над полем есть короткая шпаргалка с 2–3 примерами (фильтр, выбор колонок, группировка).
- Ошибки Python выводятся текстом (traceback), страница не ломается. Кнопка «Остановить» перезапускает воркер, если код выполняется слишком долго.

### 9.4 Общее для всех режимов

- Результат выводится таблицей с русскими заголовками (`columns.js`) и счётчиком строк. На экране показываются первые 1000 строк, в выгрузку попадают все.
- Кнопка «Скачать .xlsx» (см. раздел 8).

## 10. Этапы работы

1. Каркас: `index.html`, стили, загрузка всех CSV в `data.js`, вывод в консоль числа строк по каждой таблице.
2. Мультиселекты месторождений и скважин с «Выбрать все», флаги.
3. `query.js`: выборка таблиц 1–3 по фильтру.
4. Вкладки по месторождениям и рендер таблиц 1–3, скрытие пустых колонок.
5. Таблицы 4 (PVT) и 5 (раздел 2) по флагам.
6. Выгрузка .xlsx.
7. Боковая панель: каркас, загрузка DuckDB-WASM, SQL-режим.
8. Конструктор выборки: `schema.js`, `builder-sql.js` (с проверкой сгенерированного SQL на примерах), затем `builder-ui.js`.
